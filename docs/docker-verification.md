# Проверка полного проекта в Docker

Проверено 11 ноября 2026 года, Asia/Qyzylorda.

## Окружение

- `bd6-api-1`: Python 3.12, FastAPI, PyMongo, CLI и служебные скрипты.
- `bd6-mongo-1`: официальный образ `mongo:8.0`, фактическая версия MongoDB **8.0.34**.
- Временный сервис `tests`: тот же образ приложения, тесты подключены read-only.
- API: <http://127.0.0.1:8001/docs>.
- MongoDB для Compass: `mongodb://127.0.0.1:27018/`.
- Внутри Docker приложение обращается к `mongodb://mongo:27017/`.
- Рабочая база: `edge_catalog`. Другие СУБД проектом не используются.

## Запуск и данные

`docker compose up -d --build --wait` успешно собрал и запустил стек.
Генератор внутри API-контейнера создал 100 пользователей, 60 моделей и 100 000 событий.
Затем CLI добавил один демонстрационный просмотр. Итог: **100 / 60 / 100 001**.
Характеристики моделей и сгенерированные действия являются синтетическими.

## Автоматические тесты и реальные HTTP-запросы

`docker compose run --rm tests`:

```text
18 passed, 1 warning in 4.28s
```

Пропусков и ошибок нет. Предупреждение Starlette относится к будущей замене httpx
в тестовом клиенте; текущие тесты и работающий API успешно завершили проверки.
Среди тестов — авторизация, ограничения ролей, CRUD, уникальность, валидация прямых записей,
гонка повторных событий, приватная пагинация, поиск, агрегации и идемпотентность генератора.
MongoDB во всех этих интеграционных проверках работала в контейнере, не на хосте.

`docker compose run --rm tests ruff check app tests scripts`: **All checks passed**.

`docker compose exec -T api python -m app.cli demo`: код завершения **0**.
CLI выполнил вход, чтение профиля и каталога, запись просмотра, чтение истории,
подбор моделей и запрос аналитики через настоящий HTTP-сервер.

Со стороны хоста `/health` на порту 8001 вернул
`{"status":"ok","database":"connected"}`, а `/docs` вернул HTTP 200.
Экспорт скриптом `scripts/export_evidence.py` также подтвердил работу API, рейтингов,
популярности, статистики модели и подключения к контейнерной MongoDB.

## Индексный эксперимент

Измерения сделаны до CLI-демонстрации, на ровно 100 000 событиях. Пять запусков каждого пути.

| Метрика | Natural scan | Индекс user_recent |
|---|---:|---:|
| Возвращено документов | 20 | 20 |
| Просмотрено документов, медиана | 100 000 | 20 |
| Просмотрено ключей за запуск | 0 | 20 |
| Медиана executionTimeMillis | 38 ms | 0 ms |
| Стадии | COLLSCAN, SORT | IXSCAN, FETCH, LIMIT |

Состав индекса: `user_id ASC, created_at DESC, _id DESC`.
Проверено совпадение результатов по идентификаторам. `0 ms` — значение счётчика
с миллисекундным разрешением. Измерение не является оценкой общей производительности
системы под нагрузкой. Использован `hint` для сравнения конкретных путей доступа.

## Сохранность данных

Контейнер MongoDB перезапущен, проверено состояние healthy, затем перезапущен API.
Количество записей до и после совпало: 100 пользователей, 60 моделей, 100 001 событие.
API повторно подключился к базе. Данные находятся в именованном томе `bd6_mongo_data`.
Локальный сервер MongoDB вне Docker в этой проверке не участвовал.
